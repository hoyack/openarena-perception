2. **Add `populate_danger_zones` method**:
   ```python
   def populate_danger_zones(self, spatial: SpatialKnowledge) -> int:
       """Query death heatmap and record top danger zones. Returns count populated."""
       if self._episodic_memory is None or not self._map_name:
           return 0
       heatmap = self._episodic_memory.get_death_heatmap(self._map_name)
       if not heatmap:
           return 0
       # Sort by death count descending, take top 10 max (prevent blocking all paths)
       sorted_zones = sorted(heatmap, key=lambda x: x[3], reverse=True)[:10]
       count = 0
       for x, y, z, deaths in sorted_zones:
           if deaths >= 2:  # Only zones with repeated deaths
               # Map position to nearest area -- use simple grid approximation
               # record_danger uses area_id, approximate from position
               area_id = int(abs(x) * 31 + abs(y) * 17) % 10000  # hash to area-like ID
               spatial.record_danger(area_id)
               count += 1
       return count
   ```

   NOTE: The area_id hashing is an approximation. The existing `SpatialKnowledge.record_danger(area_id)` uses area IDs from the AAS navigation mesh. If NavBehavior has access to the navigator's area lookup (e.g., `navigator.area_for_position(x, y, z)`), use that instead. Check if `self._navigator` (likely stored from construction) has such a method. If not, the hash approximation is acceptable for v1 -- danger zone decay (30s) prevents permanent avoidance.

3. **Call on respawn**: In `on_enter_exploring()`, call `self.populate_danger_zones(spatial)` if spatial is available. Add optional `spatial: SpatialKnowledge | None = None` parameter to `on_enter_exploring()` if it doesn't already accept it. If it cannot accept new params due to existing callers, call populate_danger_zones from TacticalFSM.on_enter_state() for EXPLORING instead (document this in the summary).

Backward compat: episodic_memory=None means no adaptive learning (identical to current behavior).

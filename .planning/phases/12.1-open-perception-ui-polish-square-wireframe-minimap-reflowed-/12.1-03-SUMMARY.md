# Phase 12.1 Plan 03: Square Minimap + AAS Current-Floor Overhead + Learned Emphasis Summary

Reworked the Open-Perception minimap from a rectangular raw-occupancy view into a 360x360 square that overlays current-floor AAS polygons underneath bright learned-path cells, so the panel shows what the bot has _learned_ about the floor it is currently standing on.

## What Was Built

### Task 1 — MinimapPanel rework + app wiring

`openarena_perception/visualization/panels/minimap.py`:

- Added `from openarena_perception.navigation.aas_parser import areas_on_floor` at module top.
- `__init__` signature flipped to `(aas_graph: Any = None, width: int = 360, height: int = 360)`. `aas_graph` is the first positional so the app's keyword-based construction reads naturally; tests pass `aas_graph=None` explicitly.
- Square layout: `_map_margin = 8`, `_map_top = 24`, `_map_size = min(360-16, 360-24-8) = 328`.
- New helper `_draw_aas_overhead(state, surface)`:
  - No-op when `self._aas_graph is None` or `areas_on_floor` raises.
  - Resolves `bot_z` from `state.player_z`, then calls `areas_on_floor(graph, bot_z, z_tolerance=24.0)`.
  - For each returned area index (skipping 0 / out-of-range), projects `(mins[0], mins[1])..(maxs[0], maxs[1])` through `_world_to_minimap` and draws a filled `pygame.Rect` at `(35, 45, 60)` with a 1px `RGB_GRID` outline.
- `_draw_aas_overhead` is invoked inside `draw()` AFTER the grid lines but BEFORE the learned_map cells — guarantees learned cells paint over the AAS overhead (learned emphasis).
- Learned-map cell rendering reworked: each cell state maps to `((r,g,b), brush_size, alpha)`:
  - `1` OPEN — `(30,80,30)` size 4, alpha 80 (dim small)
  - `2` WALL — `(180,40,40)` size 4, alpha 120
  - `3` VISITED — `(60,180,60)` size 6, alpha 220 (brighter + larger — learned emphasis)
  - `4` LIQUID — `(40,40,180)` size 4, alpha 100
- Player trail `pygame.draw.lines` thickness bumped from 1 to 2.
- Area label moved to `(self._map_margin, 6)` to fit inside the 24px top strip.
- Dedup contract preserved: still no `HP:`/`AR:`/`Ammo:`/`Pos:`/`Yaw:` strings in the minimap source.

`open_perception.py`:

- `OpenPerceptionApp.__init__` now constructs the minimap as `MinimapPanel(aas_graph=aas_graph, width=PANEL_MINIMAP_SIZE, height=PANEL_MINIMAP_SIZE)`. Same `aas_graph` instance already passed to `WireframePanel`.

### Task 2 — Panel tests

`tests/test_open_perception_panels.py`:

- Flipped existing `MinimapPanel(PANEL_MINIMAP_SIZE, PANEL_MINIMAP_SIZE)` call sites to explicit keyword form `MinimapPanel(aas_graph=None, width=PANEL_MINIMAP_SIZE, height=PANEL_MINIMAP_SIZE)` via `replace_all`.
- Added `_count_aas_fill_pixels(surface)` helper that counts pixels exactly equal to `(35, 45, 60)` — necessary because the baseline map-rect fill `(30, 30, 40)` is already non-bg, so generic `_any_nonbg` cannot isolate AAS contribution.
- Added 4 new tests (all passing):
  1. `test_minimap_panel_square_layout_dimensions` — asserts `width=height=360`, `_map_margin=8`, `_map_top=24`, `_map_size=328`.
  2. `test_minimap_panel_aas_overhead_draws_polygons` — panel with graph has `>0` AAS-fill pixels; panel without graph has exactly `0`.
  3. `test_minimap_panel_aas_overhead_filtered_to_floor` — at `player_z = mid_z(area1)` AAS-fill pixels `> 0`; at `player_z = max_z + 500` AAS-fill pixels `== 0`.
  4. `test_minimap_panel_visited_cells_brighter_than_open` — renders one VISITED and one OPEN cell, masks out the player marker (RGB_PLAYER is also green-dominant), asserts bright-green pixels remain from the VISITED tile.

**1. [Rule 1 - Bug] Test assertion reworked to count AAS fill color instead of generic nonbg**
- **Found during:** Task 2 verification
- **Issue:** `test_minimap_panel_aas_overhead_filtered_to_floor` originally asserted `_any_nonbg(surf_on) > _any_nonbg(surf_above)`, but both surfaces return identical 107720 non-bg counts because the minimap's empty grid interior is painted `(30,30,40)` — already non-bg — and the AAS fill only changes the color *within* the interior from `(30,30,40)` to `(35,45,60)`. ## Decisions Made

See frontmatter `decisions:`. Key calls:

- Draw order AAS-fill → learned cells → trail puts "what the bot knows exists" underneath "what the bot has actually traversed", so the learned layer visually dominates the overhead overlay.
- AAS fill color `(35,45,60)` was tuned to stay below both VISITED green `(60,180,60)` and the grid interior `(30,30,40)` in luminosity so the overlay reads as a subtle hint, not a primary element.
- Tests count specific pixel colors instead of generic nonbg to sidestep the baseline grid contamination.

<objective>
Build the PerceptionPipeline orchestrator that wires all perception sub-modules together, manages tick budgets with rate-limiting and attention-based priority, and produces immutable SituationalAwareness snapshots every tick.

Purpose: This is the heart of Phase 2 -- the single class that game loop consumers will call instead of manually orchestrating individual detectors. It implements the attention-based filtering concept from the FPS Bot Spec (Section 2.2) where combat state increases tracker frequency and decreases anomaly detection frequency.

Output: pipeline.py with PerceptionPipeline class, config.py with PerceptionPipelineConfig, updated __init__.py exporting the pipeline.
</objective>

```python
"""Perception pipeline configuration."""
from dataclasses import dataclass


@dataclass(frozen=True)
class PerceptionPipelineConfig:
    """Tick budget and rate-limiting configuration for the perception pipeline."""
    # Rate limits (run every N ticks)
    hud_ocr_interval: int = 30        # ~2s at 15 FPS -- Tesseract is ~1800ms
    motion_interval: int = 2           # every other tick
    tracker_interval: int = 2          # every other tick
    anomaly_interval: int = 3          # every 3rd tick

    # Attention overrides during combat
    combat_tracker_interval: int = 1   # every tick during combat
    combat_anomaly_enabled: bool = False  # skip anomaly during combat

    # Death reset
    reset_on_death: bool = True
```

**2. `openarena_perception/perception/pipeline.py`** -- The main orchestrator:

Create a `PerceptionPipeline` class that:
- Accepts a `PerceptionPipelineConfig` and a `PerceptionConfig` (from existing config.py) in __init__
- Lazily constructs sub-modules (ScreenCapture, HUDParser, WorldParser, Perception/wall_detector, MotionDetector, PlayerDetector, ObjectTracker, DamageTracker, MotionAnomalyTracker) in __init__
- Has a `tick(pos=None, yaw=0.0, area=0, nav_state=None, spatial=None) -> SituationalAwareness` method
- Inside tick():
  a. Grab frame via ScreenCapture
  b. Increment tick counter
  c. ALWAYS run: enemy detection (WorldParser.parse_enemies), wall detection (Perception.detect_wall_ahead), damage tracking (DamageTracker.update)
  d. Rate-limited: HUD OCR (every hud_ocr_interval ticks), motion detection (every motion_interval ticks), object tracking (every tracker_interval ticks), anomaly detection (every anomaly_interval ticks)
  e. Attention-based priority: if under_attack or enemies_visible > 0, use combat_tracker_interval for tracking and disable anomaly per combat_anomaly_enabled
  f. On death (is_alive becomes False): call reset() on ObjectTracker and MotionAnomalyTracker if reset_on_death is True
  g. Call build_situational_awareness() to assemble the frozen SituationalAwareness snapshot

Also create the `build_situational_awareness()` standalone function in pipeline.py that maps detector outputs to SituationalAwareness fields. Follow the exact mapping from the RESEARCH.md Pattern 3 section. Key derivations:
- disposition: dead/critical/wounded/healthy based on health thresholds (0, 30, 60)
- armament: unarmed/light/armed based on weapon and ammo (<5 is light)
- orientation: "oriented" if pos is provided, else "lost"
- is_alive: True if health is None or health > 0

The pipeline must store the last HUD dict between OCR runs (self._last_hud = {}), the last motion detections, the last tracked objects list, and the last anomalies list to return fresh data even on ticks where rate-limited operations don't run.

IMPORTANT: The MotionAnomalyTracker constructor requires parameters. Read the actual constructor signature from perception/motion_anomaly.py and pass reasonable defaults. If it needs an Ollama URL or model name, use settings from BotSettings or sensible defaults. The identify_anomaly() method must NOT be called from the pipeline (it blocks for 750ms-4s).

IMPORTANT: The ScreenCapture constructor needs parameters too. Read capture.py for the make_capture() factory function and use it, or construct ScreenCapture with defaults.

IMPORTANT: Handle the case where sub-modules raise exceptions gracefully -- log the error and continue with default/empty values. The pipeline must never crash on a single detector failure.

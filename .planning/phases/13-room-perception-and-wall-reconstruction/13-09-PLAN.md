<why_13_08_failed>
READ THIS BEFORE TOUCHING ANY CODE.

Plan 13-08 applied dedup at the wrong layer: it keyed by sorted **corner-ID tuple**, assuming two cycles through "the same" corner would share IDs. Measured reality on oa_dm1 floor 0:

- `CornerDetector` emits **near-duplicate corners** at slightly different midpoints because the "nearest endpoint pair" between two walls varies by a few units across enumerations. 45 corners clustered into ~10-15 spatial groups of 2-4 corners each, each with a **distinct ID**.
- Dedup by corner-ID tuple was therefore useless. Cycles using structurally the same corner landed on different ID tuples and both got emitted.
- `endpoint_max_dist 64 -> 96` made the corner over-generation WORSE (30 -> 45 corners).
- No MAX_ROOM_AREA cap let 500k+ sq unit map-spanning cycles slip through.

Result: 65 rooms -> 487 rooms, 8411 centroid-pair collisions within 32u.

**The right fix is spatial at the corner level, not at the cycle level.** Merge near-duplicate corners at the source in `CornerDetector`, then dedup rooms by centroid cell in `RoomInferrer`, then cap absurd areas. Revert the 96u endpoint bump. The existing test suite did not exercise over-connected graphs with near-duplicate corners — this plan adds that regression test so we catch the next version of this bug pre-live.

3. After the existing `for w1, w2 in itertools.combinations(...)` loop finishes building the raw `corners` list, run a spatial merge pass BEFORE returning. Implementation (simple O(n^2) repeated-nearest collapse; typical n <= 50 on Pi so perfectly acceptable):

```python
# Plan 13-09: spatial merge pass. CornerDetector's pair enumeration
# emits near-duplicate corners at slightly different midpoints when
# the same two walls' "nearest endpoint" calculation varies by a few
# units. Collapse corners within merge_radius into one, using the
# midpoint of each merged cluster. This kills the 13-08 corner-ID-tuple
# dedup failure at the source.
if self.merge_radius > 0.0 and corners:
    merged: List[Corner] = []
    for c in corners:
        absorbed = False
        for i, m in enumerate(merged):
            dx = c.x - m.x
            dy = c.y - m.y
            if (dx * dx + dy * dy) ** 0.5 < self.merge_radius:
                # Merge: midpoint, min confidence, average angle.
                new_x = (m.x + c.x) / 2.0
                new_y = (m.y + c.y) / 2.0
                new_conf = min(m.confidence, c.confidence)
                new_angle = (m.angle_deg + c.angle_deg) / 2.0
                # Keep the existing wall_a/wall_b on the retained corner.
                # If the incoming corner references a THIRD wall not
                # already in {m.wall_a_id, m.wall_b_id}, log once and
                # drop the third reference. Corner NamedTuple only has
                # two wall slots; widening it is out of scope.
                incoming_walls = {c.wall_a_id, c.wall_b_id}
                existing_walls = {m.wall_a_id, m.wall_b_id}
                if not incoming_walls.issubset(existing_walls):
                    extra = incoming_walls - existing_walls
                    _log.warning(
                        "CornerDetector.merge: third wall(s) %s at merged "
                        "corner (%.1f, %.1f) ignored; Corner slots full",
                        sorted(extra), new_x, new_y,
                    )
                merged[i] = m._replace(
                    x=new_x, y=new_y,
                    confidence=new_conf, angle_deg=new_angle,
                )
                absorbed = True
                break
        if not absorbed:
            merged.append(c)
    # Reassign sequential ids 1..N so downstream code sees a clean set.
    corners = [
        m._replace(id=i + 1) for i, m in enumerate(merged)
    ]
return corners
```

Notes:
- Use `corner._replace(...)` — NamedTuple is immutable.
- The id reassignment at the end is important: downstream `RoomInferrer` builds its adjacency from `(c.wall_a_id, c.wall_b_id)` pairs (not ids), so reassigning ids is safe and gives us a tidy sequential list.
- The merge is a single pass over raw corners. It is NOT transitive (we don't re-scan merged clusters for further collapse). For the live data regime (~10-15 clusters of 2-4 near-duplicates) a single pass is sufficient. Document this in the inline comment: "single-pass non-transitive merge; adequate for live n<=50 regime".

```python
@staticmethod
def _polygon_perimeter(polygon: List[Tuple[float, float]]) -> float:
    n = len(polygon)
    if n < 2:
        return 0.0
    total = 0.0
    for i in range(n):
        x1, y1 = polygon[i]
        x2, y2 = polygon[(i + 1) % n]
        total += ((x2 - x1) ** 2 + (y2 - y1) ** 2) ** 0.5
    return total
```

```python
@staticmethod
def _polygon_centroid(polygon: List[Tuple[float, float]]) -> Tuple[float, float]:
    if not polygon:
        return (0.0, 0.0)
    sx = sum(p[0] for p in polygon)
    sy = sum(p[1] for p in polygon)
    n = len(polygon)
    return (sx / n, sy / n)
```

```python
def test_corner_spatial_merge():
    """Plan 13-09: near-duplicate corners at one logical intersection merge to one."""
    from openarena_perception.navigation.room_perception import (
        CornerDetector,
        Wall,
    )

    # Four walls forming an L whose endpoints are slightly offset so
    # pair enumeration would emit multiple near-duplicate corners near
    # (0, 0). Distances between the near-duplicates should be < 8u.
    w1 = Wall(1, 0, 0, 100, 0, 0.9, 30, 0.0, 1.0)
    w2 = Wall(2, 2, 1, 102, 1, 0.9, 30, 0.0, 1.0)   # parallel-ish to w1
    w3 = Wall(3, 0, 0, 0, 100, 0.9, 30, 0.0, 1.0)
    w4 = Wall(4, 1, 2, 1, 102, 0.9, 30, 0.0, 1.0)   # parallel-ish to w3

    walls = [w1, w2, w3, w4]
    raw = CornerDetector(merge_radius=0.0).detect(walls)
    merged = CornerDetector(merge_radius=16.0).detect(walls)
    assert len(merged) < len(raw), (
        f"merge should reduce count: raw={len(raw)}, merged={len(merged)}"
    )
    # No two merged corners should sit within merge_radius of each other.
    for i in range(len(merged)):
        for j in range(i + 1, len(merged)):
            dx = merged[i].x - merged[j].x
            dy = merged[i].y - merged[j].y
            d = (dx * dx + dy * dy) ** 0.5
            assert d >= 16.0, (
                f"merged corners {i} and {j} still within merge_radius "
                f"({d:.2f} < 16.0)"
            )
```

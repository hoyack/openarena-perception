# Getting Started

This guide walks you through setting up OpenArena Perception on a Raspberry Pi -- from a bare Pi to a running bot.

## Prerequisites

- **Raspberry Pi 4 or 5** (4GB+ RAM recommended; 8GB for LLM support)
- **Raspberry Pi OS Bookworm** (64-bit) -- ships with Python 3.11+
- **OpenArena** installed and runnable (see OpenArena Setup below)
- **Python 3.11+** (pre-installed on Bookworm)
- **X11 display server** (default on Pi OS with desktop)
- **Tesseract OCR** (`sudo apt install tesseract-ocr`)
- **uv package manager** (installed in the Installation step)

**Optional:**
- **Ollama** for LLM strategic reasoning (can be disabled)
- **Hailo-8L NPU** for accelerated YOLO inference (Pi 5 AI Kit)

## Installation

### 1. Install System Dependencies

```bash
# Update system packages
sudo apt update && sudo apt upgrade -y

# Install Tesseract OCR (required for HUD parsing)
sudo apt install -y tesseract-ocr

# Install build essentials (for native Python packages)
sudo apt install -y build-essential python3-dev

# Install X11 libraries (for screen capture via mss)
sudo apt install -y libx11-dev libxext-dev libxrandr-dev
```

### 2. Clone the Repository

```bash
git clone https://github.com/your-org/openarena-perception.git
cd openarena-perception
```

### 3. Install uv Package Manager

```bash
curl -LsSf https://astral.sh/uv/install.sh | sh
```

Restart your shell or run `source ~/.bashrc` to make `uv` available.

### 4. Install Python Dependencies

```bash
# Install all dependencies (creates .venv automatically)
uv sync

# Install dev dependencies too (for running tests)
uv sync --group dev
```

### 5. Verify Installation

```bash
# Run the test suite -- all tests should pass
uv run pytest -x -q
```

If all tests pass, the installation is complete.

## OpenArena Setup

### Installing OpenArena

```bash
# Install OpenArena from the Debian/Raspbian repositories
sudo apt install -y openarena

# Verify it launches (will open a game window)
openarena
```

If the package is not available, download from the [OpenArena website](http://openarena.ws/download.php) and extract to `~/.openarena/`.

### Configuring the Named Pipe

The bot communicates with the game engine via a named pipe. Create it before starting the game:

```bash
# Create the named pipe
mkfifo /tmp/openarena_pipe

# Verify it exists
ls -la /tmp/openarena_pipe
# Expected: prw-r--r-- ... /tmp/openarena_pipe
```

Start OpenArena with stdin redirected from the pipe:

```bash
# Start OpenArena reading commands from the pipe
openarena < /tmp/openarena_pipe &
```

The bot writes Q3 console commands (movement, firing, turns) to this pipe.

### RCON Setup

RCON (Remote Console) allows the bot to query game state via UDP. Add to your OpenArena server config (`~/.openarena/baseoa/autoexec.cfg`):

```
seta rcon_password "your-secure-password"
seta sv_port 27960
```

Then set the matching password in your bot configuration:

```bash
# In .env file
OA_RCON_PASSWORD=your-secure-password
OA_RCON_PORT=27960
```

### Loading AAS Navigation Files

AAS (Area Awareness System) files contain pre-computed navigation meshes for each map. The bot uses these for A* pathfinding.

```bash
# AAS files should be in the maps/ directory
ls maps/
# Expected: dm4ish.aas, q3dm1.aas, etc.

# Set the map name and AAS directory in your config
echo 'OA_MAP_NAME=dm4ish' >> .env
echo 'OA_AAS_DIR=maps' >> .env
```

AAS files are generated by the Q3 `bspc` tool from BSP map files. Pre-generated AAS files for common OpenArena maps are included in the `maps/` directory.

## Calibration

### Screen Resolution

The bot captures the game window via `mss`. The configured resolution must match the actual game window size.

```bash
# Check your OpenArena resolution
# In the OpenArena console (press ~):
# /r_customwidth
# /r_customheight

# Set matching values in .env
echo 'OA_SCREEN_W=800' >> .env
echo 'OA_SCREEN_H=600' >> .env
```

800x600 is recommended for Pi -- lower resolution means faster frame processing and higher FPS.

### Enemy Color Mode

The perception system detects enemies via HSV color thresholding. Set the color mode to match the enemy team:

```bash
# If enemies appear RED in-game:
echo 'OA_ENEMY_COLOR_MODE=red' >> .env

# If enemies appear BLUE in-game:
echo 'OA_ENEMY_COLOR_MODE=blue' >> .env
```

The default is `red`. This depends on which team the bot joins -- enemies are always the opposite team color.

### HUD Region Calibration

The OCR system reads health, armor, ammo, weapon name, frags, and deaths from fixed screen regions. These regions are calibrated for 800x600 resolution. If using a different resolution, the HUD region coordinates in the perception pipeline may need adjustment.

At 800x600 (default):
- Health: bottom-left corner
- Armor: above health
- Ammo: bottom-right corner
- Weapon: right of ammo
- Frags/Deaths: top area

### Yaw Calibration

The bot converts pixel offsets to yaw angles for aiming. The Q3 engine uses the formula:

```
yaw_degrees = pixel_offset * (sensitivity * m_yaw) / screen_width * fov
```

Where:
- `sensitivity` = Q3 `sensitivity` cvar (default: 5.0)
- `m_yaw` = Q3 `m_yaw` cvar (default: 0.022)
- `fov` = field of view in degrees (default: 90)

The virtual controller handles this conversion internally. If aim appears miscalibrated, check that Q3 cvars match the expected values by querying via RCON.

## First Run

### 1. Start OpenArena

```bash
# Create the named pipe (if not already created)
mkfifo /tmp/openarena_pipe 2>/dev/null

# Start OpenArena with pipe input
openarena +set com_pipefile openarena_pipe &

# Wait for the game to load, then join a match
```

### 2. Start the Bot

```bash
# Run the perception loop (main bot brain)
uv run python -m openarena_perception.loop
```

The bot will begin:
1. Capturing the screen via `mss`
2. Detecting enemies via HSV color thresholding
3. Reading HUD values via OCR
4. Making navigation and combat decisions
5. Sending commands via the named pipe

### 3. Start the API Server (Optional)

The FastAPI server provides real-time bot state, skill execution, and WebSocket streaming:

```bash
# Start the API server
uv run uvicorn openarena_perception.api.app:create_app --factory --host 0.0.0.0 --port 8420
```

Endpoints:
- `GET http://localhost:8420/health` -- health check
- `GET http://localhost:8420/perception/state` -- current perception state
- `POST http://localhost:8420/skills/actions/{name}` -- execute a skill action
- `WS ws://localhost:8420/ws/state` -- real-time bot state stream

### 4. Verify the Bot Is Playing

```bash
# Check API health
curl http://localhost:8420/health

# Check perception state
curl http://localhost:8420/perception/state

# Watch the game window -- the bot should be moving, shooting, and navigating
```

## Troubleshooting

### Pipe Not Found

**Symptom:** Bot fails to start with "pipe not found" or "No such file or directory".

**Cause:** The named pipe does not exist or OpenArena is not reading from it.

**Fix:**
```bash
# Recreate the pipe
rm -f /tmp/openarena_pipe
mkfifo /tmp/openarena_pipe

# Restart OpenArena with pipe input
openarena +set com_pipefile openarena_pipe &
```

### OCR Not Reading HUD

**Symptom:** Health, armor, and ammo values are always 0 or `None`.

**Cause:** Screen resolution mismatch, Tesseract not installed, or HUD regions miscalibrated.

**Fix:**
1. Verify Tesseract is installed: `tesseract --version`
2. Verify resolution matches: `OA_SCREEN_W` and `OA_SCREEN_H` must match the actual game window
3. Check `OA_OCR_UPSCALE` -- increase to 4 or 5 if digits are blurry
4. Ensure the game window is fully visible (not occluded by other windows)

### Bot Stuck / Not Moving

**Symptom:** Bot is running but not moving in-game.

**Cause:** Named pipe is not connected, AAS file missing, or bot is in DEAD state.

**Fix:**
1. Verify the pipe is connected: `echo "+forward" > /tmp/openarena_pipe` -- the bot should move forward
2. Verify AAS file exists for the current map: `ls maps/<map_name>.aas`
3. Check API state: `curl http://localhost:8420/perception/state` -- look for the current FSM state
4. Check logs for stuck recovery messages

### LLM Timeout

**Symptom:** Strategy decisions are very slow or timing out.

**Cause:** Ollama not running, model too large, or network issue.

**Fix:**
1. Verify Ollama is running: `curl http://localhost:11434/api/tags`
2. Try a smaller model: `OA_OLLAMA_MODEL=gemma3:1b`
3. Disable LLM entirely: `OA_LLM_ENABLED=false` -- the bot will use rule-based decisions
4. If using remote Ollama: check `OA_OLLAMA_BASE_URL` points to the correct host

### Low FPS / High CPU

**Symptom:** Bot is sluggish, FPS below 10, tick budget warnings in logs.

**Cause:** Pi hardware struggling with the default settings.

**Fix:**
1. Lower target FPS: `OA_TARGET_FPS=10`
2. Lower tick budget: `OA_TICK_BUDGET_MS=40`
3. Disable LLM: `OA_LLM_ENABLED=false`
4. Lower OCR frequency: increase `hud_ocr_interval` in perception config
5. Close other applications consuming CPU

See the [Configuration Guide](configuration.md) for detailed tuning recommendations.

### Permission Denied on Pipe

**Symptom:** "Permission denied" when writing to the named pipe.

**Cause:** Pipe created by a different user or with wrong permissions.

**Fix:**
```bash
rm -f /tmp/openarena_pipe
mkfifo -m 666 /tmp/openarena_pipe
```

### Ollama Installation (Optional)

If you want LLM strategic reasoning:

```bash
# Install Ollama
curl -fsSL https://ollama.com/install.sh | sh

# Pull the default model
ollama pull gemma3:4b

# Verify it works
ollama run gemma3:4b "Hello, world"
```

On Pi 4 with limited RAM, use `gemma3:1b` instead. On Pi 5 with 8GB, `gemma3:4b` works well.
